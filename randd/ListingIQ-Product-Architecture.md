# ListingIQ — Multi-Agent Product Listing Optimization Engine

## Product Vision

ListingIQ is an AI-powered multi-agent system that helps enterprise marketing teams optimize their ecommerce product listings by benchmarking them against top competitors, scoring them across multiple dimensions, and generating actionable recommendations with optimized rewrites.

The core value proposition: A brand's marketing team pastes their product listing (title + description), and the system runs a competitive intelligence pipeline that tells them exactly how their listing compares to the top 10 competitors in that subcategory, scores them on every dimension that matters for conversion, and gives them specific suggestions to close the gaps — automatically, at scale, across their entire catalog.

---

## Target Market

### Primary Verticals

**1. Supplements & Nutraceuticals**
Supplement buyers are the most obsessive label readers in ecommerce. They check ingredient forms, dosages, certifications, allergen statements, and bioavailability claims before purchasing. Every word in the listing directly impacts the purchase decision.

Target companies: NOW Foods, Nature Made, Nature's Bounty, Garden of Life, Vital Proteins, Athletic Greens (AG1), Thorne, Life Extension, Himalaya, Jarrow Formulas, plus DTC supplement brands on Amazon.

**2. Beauty & Cosmetics (Skincare Focus)**
Skincare buyers obsessively compare ingredient concentrations, formulation types, skin type suitability, and certifications before purchasing. The listing copy is the primary conversion driver after price.

Target companies: L'Oreal Group (Garnier, Maybelline, CeraVe, La Roche-Posay), Estee Lauder Companies (Clinique, The Ordinary/DECIEM), Unilever (Dove, Simple), Shiseido, Amorepacific (Laneige), Medicube, Anua, plus DTC skincare brands.

### Why These Verticals

Both verticals share a critical characteristic: they are "read before buy" categories. Buyers put these products in their body or on their face, so they read every word of the listing. This means listing quality directly drives conversion, making the optimization tool's value immediately measurable. Both also have high SKU velocity (constant new formulations, variants, seasonal launches) that makes manual optimization impossible at scale.

### Enterprise Buyer Personas

- Head of Ecommerce / Digital Commerce — owns P&L for online channels
- Brand Manager — owns product market performance
- Content Operations Manager — manages listings across platforms
- Ecommerce Agency (manages listings for multiple brands)

## Agent Pipeline Architecture

### Pipeline Overview

The system is built as a LangGraph multi-agent pipeline with 8 agents. After the category classifier, the pipeline forks into two parallel branches (competitor research and user listing analysis) that merge at the benchmark scorer.

```
User Input
    |
[Input Parser Agent] — normalize, extract entities
    |
[Category Classifier Agent] — determine subcategory, load scoring rubric
    |
    +------ PARALLEL FORK ------+
    |                           |
[Competitor Scout]         [Listing Analyzer]
Find top 10 listings       Parse user's listing
    |                      against rubric dimensions
[Competitor Analyzer]           |
Extract patterns,               |
keywords, claims                |
    |                           |
    +------ MERGE ------+
            |
    [Benchmark Scorer]
    Score user vs competitors
    per dimension (0-10)
            |
    [Recommendation Engine]
    Gap-based prioritized
    suggestions
            |
    [Rewrite Generator]
    2-3 optimized variants
    for A/B testing
```

### Agent 1: Input Parser

- Model: Haiku (fast structured extraction)
- Input: Raw product title and description from user
- Responsibilities: Normalize text, extract entities (product type, brand, ingredients, certifications, target audience), detect platform (Amazon, Shopify, Daraz)
- Output: Cleaned and structured product data, platform identifier

### Agent 2: Category Classifier

- Model: Sonnet (needs reasoning for subcategory mapping)
- Input: Structured product data from Agent 1
- Responsibilities: Map product to vertical > category > subcategory hierarchy, load the corresponding scoring rubric template with dimensions and weights
- Output: Category path, scoring rubric with weighted dimensions

### Agent 3: Competitor Scout (parallel branch 1)

- Model: Haiku (execution agent, follows instructions)
- Input: Subcategory, platform
- Tools: Amazon Product Advertising API / Rainforest API, scraping tools (Playwright, Bright Data), platform-specific APIs
- Responsibilities: Search for subcategory keywords, find top 10 competitor listings by sales rank or review count, extract title, bullet points, description, price, rating, review count, badges
- Output: List of 10 structured competitor listing objects

### Agent 4: Competitor Analyzer (continues from Agent 3)

- Model: Sonnet (pattern extraction across 10 listings requires reasoning)
- Input: 10 competitor listings, scoring rubric
- Responsibilities:
  - Keyword frequency map: which keywords appear in 7+ of top 10 titles
  - Claim patterns: which claims are made by top sellers (e.g., "third-party tested" in 9/10)
  - Trust signal inventory: certifications and badges across competitors
  - Structural patterns: average title length, bullet count, description length, use of emojis
  - Differentiation analysis: what top 3 have that bottom 7 don't
- Output: Competitive intelligence report with keyword maps, claim inventories, structural benchmarks, differentiation gaps

### Agent 5: Listing Analyzer (parallel branch 2)

- Model: Sonnet
- Input: User's cleaned listing, scoring rubric
- Responsibilities: For each dimension in the rubric, extract what the user's listing currently has. For a magnesium supplement: is form specified (yes/no, which form), is dosage stated (yes/no, value), is third-party testing mentioned (yes/no, which body), etc.
- Output: Per-dimension extraction from user's listing

### Agent 6: Benchmark Scorer (merge point)

- Model: Sonnet or Opus (highest-stakes reasoning, needs accuracy)
- Input: User's listing dimensions, competitor analysis, scoring rubric
- Responsibilities: For each dimension in the rubric, score the user's listing 0-10 by comparing against competitor benchmark. Calculate weighted overall score. Identify gaps ranked by (gap size x dimension weight).
- Output: Per-dimension scores, overall weighted score, competitor benchmark averages, ranked gap analysis

### Agent 7: Recommendation Engine

- Model: Sonnet (needs to generate specific, actionable suggestions)
- Input: Gap analysis ranked by impact
- Responsibilities: Generate prioritized recommendations with specific copy suggestions and competitive justification. Not "improve your title" but exactly what words to add, what claims to make, what certifications to highlight.
- Output: Ordered list of recommendations with specific copy suggestions, competitive evidence, and expected impact

### Agent 8: Rewrite Generator

- Model: Sonnet (creative + strategic writing)
- Input: Original listing, recommendations, competitor analysis
- Responsibilities: Generate 2-3 complete rewritten variants of title and description, each with a different strategic angle:
  - Variant A — Keyword-optimized: maximum search visibility, front-loads high-volume keywords
  - Variant B — Benefit-led: leads with strongest outcome claims, best for Shopify/DTC
  - Variant C — Trust-forward: leads with certifications and testing, best for supplements/skincare trust barrier
- Output: 2-3 complete title + description rewrites with strategy labels

## Scoring Rubric Templates

### Supplements — Magnesium Glycinate (Example)

| Dimension | Weight | What It Measures |
|---|---|---|
| Form specificity | 0.15 | Does listing specify the magnesium form (glycinate, citrate, oxide)? |
| Dosage clarity | 0.12 | Is dosage per serving clearly stated with elemental mg? |
| Third-party testing | 0.15 | USP, NSF, or ConsumerLab verification mentioned? |
| Bioavailability claims | 0.10 | Absorption or bioavailability explained? |
| Allergen/dietary callouts | 0.08 | Gluten-free, vegan, soy-free, non-GMO stated? |
| Use-case positioning | 0.12 | Specific outcomes (sleep, stress, muscle, migraine) targeted? |
| Serving value | 0.08 | Servings per container, cost per serving communicated? |
| Keyword coverage | 0.10 | Category-relevant search terms present vs top competitors? |
| Trust signals | 0.10 | GMP, FDA-registered facility, made in USA, cGMP? |

### Skincare — Vitamin C Serum (Example)

| Dimension | Weight | What It Measures |
|---|---|---|
| Concentration transparency | 0.14 | Is vitamin C percentage stated (10%, 15%, 20%)? |
| Form specificity | 0.12 | Is the form of vitamin C identified (L-ascorbic acid, SAP, AG)? |
| Ingredient synergy | 0.10 | Supporting ingredients called out (vitamin E, ferulic acid, HA)? |
| Skin type targeting | 0.10 | Suitability for specific skin types stated (oily, dry, sensitive, acne-prone)? |
| Outcome specificity | 0.10 | Specific results promised (dark spots, brightening, collagen, sun damage)? |
| Texture/sensory description | 0.06 | Product feel described (lightweight, non-greasy, fast-absorbing)? |
| Certifications | 0.10 | Vegan, cruelty-free, paraben-free, fragrance-free stated? |
| Clinical backing | 0.08 | Dermatologist-tested, clinically proven, clinical study referenced? |
| Routine positioning | 0.08 | Where it fits in a skincare routine explained (after toner, before moisturizer)? |
| Keyword coverage | 0.12 | Category-relevant search terms present vs top competitors? |

## Observability & Persistence

- LangSmith integration for agent call logging (input/output per node, latency tracking)
- Scoring results stored for trend analysis per client (track improvement over time: "listings improved from 2.6/10 to 7.8/10 over 3 months")
- Competitor data cached with TTL to avoid redundant scraping
- Rubric templates stored as versioned JSON configs (easy to add new categories)
